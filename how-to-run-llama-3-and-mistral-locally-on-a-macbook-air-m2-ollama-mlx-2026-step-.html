Introduction

Local AI on Apple Silicon is now a practical, fast, and private option for many developers and power users. This guide (accurate as of October 1, 2026) walks you through a repeatable setup on a MacBook Air M2 using Ollama for model management and MLX (mlx‑lm) for Apple‑native, high‑performance inference. You’ll get runnable commands, model recommendations for an M2 machine, troubleshooting tips, and security notes so you can run Llama 3 and Mistral locally without surprises. (developer.apple.com)

What you need (short prerequisites)

  • MacBook Air with an Apple M2 chip (8/16/24 GB unified RAM). For larger models you’ll want 16+ GB. (smeltcore.com)
  • macOS (recommendation: macOS 14+; some MLX features and larger model memory wiring work best on recent macOS builds). Check mlx/mlx‑lm docs for exact minimums. (localaiscope.com)
  • Homebrew (or willingness to install via the Ollama installer script), Xcode command line tools, and Python 3.10+ (for MLX tools). (ollama.com)

If you’re short on RAM (8 GB), prefer small 3B or lightweight quantized models (Llama 3 3B or Mistral 7B in 4‑bit). If you have 16 GB or more, 7B/8B models are comfortable; 13B+ models will likely swap and be very slow on an Air M2. (smeltcore.com)

Step 1 — Install Ollama (model manager / CLI)

Ollama is the easiest way to pull and manage popular local LLMs (including Llama 3 and many Mistral variants). Install with the official script or Homebrew; the install script is the simplest:

  • In Terminal:
  • curl -fsSL https://ollama.com/install.sh | sh
  • Confirm: ollama --version

Ollama’s quickstart docs include examples like ollama run llama3.2 and explain the pull/run workflow. (ollama.com)

Notes: - Keep Ollama updated; MLX support landed as a preview in 2026 and newer builds add more MLX-enabled models and performance improvements. If you need MLX acceleration inside Ollama, update to the current release and check the release notes. There are cases where community or custom builds are required for the experimental MLX image features — see the project notes if you hit “build with mlx” errors. (ollama.com)

Step 2 — Install MLX (mlx‑lm) — Apple’s fast runtime for M‑series

MLX (and the community package mlx‑lm) is the Apple‑native array/runtime that delivers large speedups on M‑series chips. You can either let Ollama use MLX (if your Ollama build supports it) or run MLX directly for raw performance.

Install options (choose one):

  • Homebrew (quick): brew install mlx-lm. (formulae.brew.sh)
  • pip (Python virtualenv recommended):
  • python3 -m venv ~/mlx-venv && source ~/mlx-venv/bin/activate
  • pip install --upgrade pip
  • pip install mlx-lm
  • Verify: python -c "import mlx, mlx_lm; print('mlx OK')"

Hugging Face and mlx‑lm docs show the CLI usage (mlx_lm.generate / mlx_lm.server) and how to point at models on HF or a local cache. MLX is macOS/ARM‑only. (huggingface.co)

Step 3 — Pull and run Llama 3 (Ollama)

Ollama already hosts Llama 3 variants and makes them trivial to run.

  • Pull a small/medium Llama 3 (good for M2 Air):
  • ollama pull llama3.2:3b
  • Run a quick chat:
  • ollama run llama3.2:3b
  • Or one‑shot command:
  • ollama run llama3.2:3b "Summarize the README in one paragraph."

Ollama’s docs and blog show ollama run llama3.2 examples; pick the model size that fits your RAM (3B or 8B for Air M2). If your Ollama build supports MLX backend for specific models, Ollama may choose a faster MLX runner automatically for MLX‑tagged models. (ollama.readthedocs.io)

Step 4 — Run Mistral with MLX (mlx‑lm direct)

Mistral 7B is a great fit for a MacBook Air M2 when you use quantized MLX builds (4‑bit). You can run Mistral either via Ollama (many builds available as mistral:7b) or directly with MLX for maximum throughput and lower latency.

Direct MLX server example (after installing mlx‑lm):

  • Start the MLX server (OpenAI‑compatible HTTP API):
  • mlx_lm.server --model mistralai/Mistral-7B-Instruct-v0.3 --port 8000
  • Test with curl (OpenAI‑style request):
  • curl -s -X POST "http://127.0.0.1:8000/v1/chat/completions" -H "Content-Type: application/json" -d '{"model":"mistralai/Mistral-7B-Instruct-v0.3","messages":[{"role":"user","content":"Hello from my MacBook Air M2"}]}'

Hugging Face MLX docs and the mlx‑community model pages show these exact usage patterns and provide MLX‑formatted quantized models you can download. If you prefer Ollama, you can also ollama pull mistral and run through Ollama’s CLI. (huggingface.co)

Step 5 — Hybrid workflows and choosing which runtime

  • Ollama is the easiest for management (single CLI to pull and run many models). Use Ollama when you want convenience. (ollama.readthedocs.io)
  • Use mlx‑lm when you need the fastest token throughput/lowest latency and are comfortable running a local MLX server and pointing your apps at it (it’s OpenAI‑compatible). Hugging Face and MLX packages are first‑class for Mistral models. (huggingface.co)

If your version of Ollama shows no MLX acceleration for a model, try running that same model with mlx‑lm to compare performance (some users report significant gains for certain models). (ollamaherd.com)

Performance tips (MacBook Air M2 specific)

  • Prefer quantized 4‑bit MLX builds for 7B/8B models. They dramatically reduce memory and often run faster. Use mlx‑community quantized artifacts on Hugging Face. (huggingface.co)
  • Limit context length if you see swapping. Reduce to 2–4k tokens for heavy workloads on 8–16 GB machines. (smeltcore.com)
  • Close memory‑heavy apps (Safari with many tabs, big editors) while benchmarking. MLX and Ollama rely on unified memory; avoid macOS swapping. (developer.apple.com)

Troubleshooting & security notes

  • If Ollama errors with “build with mlx” or a missing MLX runner, check that you have a recent Ollama build (some MLX features arrived as a preview) or run the model with mlx‑lm directly. There are GitHub issues documenting builds without the experimental MLX tag. (github.com)
  • If models crash or the system swaps to disk, the model is likely too large for your unified memory—choose a smaller/quantized version. (smeltcore.com)
  • Ollama runs a local server by default; make sure it isn’t exposed unintentionally to the internet. There were community reports about exposed Ollama servers and you should firewall or bind it to localhost if you don’t need remote access. (en.wikipedia.org)
