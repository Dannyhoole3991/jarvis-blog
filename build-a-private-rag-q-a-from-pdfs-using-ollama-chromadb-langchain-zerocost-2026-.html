Introduction

If you want a private, zero-cost way to ask questions of your own PDFs (contracts, manuals, internal reports), a fully local Retrieval‑Augmented Generation (RAG) stack is an excellent choice. This guide walks you through a tested 2026 workflow that uses Ollama to run local models, ChromaDB as a persistent vector store, and LangChain to orchestrate ingestion, retrieval, and generation. Everything runs on your machine — no API keys, no cloud costs, and nothing leaves your network. The instructions below are practical and runnable end-to-end.

What this stack gives you (short)

  • Ollama: local model runtime and embedding models you can pull and run on CPU/GPU. Run models locally and call them via a local HTTP API. (ollama.com)
  • ChromaDB: open-source vector database with local persistence options (disk-backed client/persist directory). (docs.trychroma.com)
  • LangChain: the orchestration and glue — loaders, splitters, embedding adapters, and chains to connect retrieval to generation (integrations for Ollama + Chroma exist). (docs.langchain.com)

Prerequisites

  • Linux/macOS/Windows machine with Python 3.10+ and enough disk space for models and the Chroma DB.
  • Install Ollama (official installer / brew / package for your OS) and allow the Ollama service to run. Ollama exposes a local API (default port 11434). (computingforgeeks.com)

Step 1 — Install and start Ollama, pull models

  1. Install Ollama (follow the official quickstart/install for your OS). Start the service (on Linux you can use ollama serve or the installed systemd unit). (ollama.readthedocs.io)
  2. Pull two models into Ollama: an embedding model (nomic-embed-text is a common, CPU-friendly choice) and a chat/generation model you prefer (examples in the Ollama library). Example commands:
  3. ollama pull nomic-embed-text
  4. ollama pull llama3.3 (or another chat model available in your Ollama library)
    The ollama pull flow downloads models into your local Ollama store so inference is free and offline. (ollama.com)

Step 3 — Ingest PDFs (code + explanation)

High-level flow: load PDFs → split into chunks → embed chunks via Ollama → store vectors in Chroma (persistent).

Example (ingest.py — annotated):

from pathlib import Path
import hashlib
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_ollama import OllamaEmbeddings
from langchain_chroma import Chroma
import chromadb

# Config
OLLAMA_BASE = "http://localhost:11434"
EMBED_MODEL = "nomic-embed-text"
CHROMA_DIR = "./chroma_data"
COLLECTION = "pdf_docs"

# Loader + splitter
loader = PyPDFLoader  # uses pypdf/pymupdf under the hood
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)

# Embeddings via local Ollama
embeddings = OllamaEmbeddings(model=EMBED_MODEL, base_url=OLLAMA_BASE)

# Persistent Chroma client + LangChain wrapper
client = chromadb.PersistentClient(path=CHROMA_DIR)
vectordb = Chroma(client=client, collection_name=COLLECTION, embedding_function=embeddings)

def stable_id(path: str, idx: int) -> str:
    return hashlib.sha256(f"{path}::chunk_{idx}".encode()).hexdigest()[:16]

def ingest_pdf(path: str):
    docs = loader(path).load()
    chunks = splitter.split_documents(docs)
    for i, c in enumerate(chunks):
        c.metadata.update({"source": Path(path).name, "chunk_index": i, "doc_id": stable_id(path, i)})
    vectordb.add_documents(chunks, ids=[c.metadata["doc_id"] for c in chunks])

This pattern — PyPDFLoader + RecursiveCharacterTextSplitter + OllamaEmbeddings + Chroma — is the standard local-RAG ingestion pipeline used across recent tutorials and examples. Persist the Chroma data directory so re-runs reuse embeddings. (academy.talki-app.fr)

Step 4 — Wire retrieval to a generator (LangChain chain)

Create a retriever and a retrieval chain that feeds the retrieved chunks to your chat LLM:

from langchain_chroma import Chroma
from langchain_ollama import ChatOllama
from langchain.chains import create_retrieval_chain, create_stuff_documents_chain

# LLM using Ollama (chat model you pulled)
llm = ChatOllama(model="llama3.3", base_url=OLLAMA_BASE)

# Load existing Chroma collection
client = chromadb.PersistentClient(path=CHROMA_DIR)
db = Chroma(client=client, collection_name=COLLECTION, embedding_function=embeddings)

retriever = db.as_retriever(search_kwargs={"k": 4})
combine_chain = create_stuff_documents_chain(llm, prompt=None)  # uses default prompt; customize if desired
rag = create_retrieval_chain(retriever, combine_chain)

# Run a query:
resp = rag.invoke({"query": "What are the termination clauses in contract X?"})
print(resp)

LangChain's API has shifted over time (the modern pattern favors create_retrieval_chain / create_stuff_documents_chain or the compatibility package langchain_classic); adapt imports to your installed LangChain version if you see deprecation/compatibility messages. The approach above is the current recommended pattern in recent LangChain guides. (markaicode.com)

Step 5 — Test, iterate, and validate sources

  • Test queries, ask for citations, and validate answers against the source chunks. Configure the chain/prompt to return source metadata so every answer includes the originating PDF + chunk index. LangChain can return sources by default when using retrieval chains. (langchain.com.cn)
  • Tweak chunk size (500–1500 tokens common), overlap (100–300), and number of retrieved docs (k) based on document types.

Tips, troubleshooting, and production notes

  • Persistence: Chroma supports a disk-persistent client; use PersistentClient / persist_directory so your embeddings survive restarts. Locking issues can appear if multiple processes try to use the same SQLite file — run one Chroma process or use the REST server mode for multi-worker deployments. (docs.trychroma.com)
  • Embedding model: nomic-embed-text is a strong, long-context open embedding model available via Ollama and works well for PDFs; it’s a common zero-cost choice. If you need better quality for short text, test alternatives. (ollama.com)
  • Ollama service: on Linux prefer running Ollama as a systemd service (installer may do this). On macOS Ollama can auto-start; on Windows you may use the installer/LaunchAgent. The local API default port is 11434. Protect that endpoint if you open it to LAN. (itechguides.com)
  • Security: your private PDFs remain local, but still consider prompt-injection and adversarial content in documents. Validate sources and prefer chains that return provenance. (stevenfoerster.com)
